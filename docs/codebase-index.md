# Codebase Index

A literal, per-file map of this repo — what lives where and what it's for — so a
session can jump straight to the right file instead of re-exploring the tree
with `find`/`grep` from scratch. This complements the other docs rather than
replacing them: `brief.md`/`api.md`/`domain-model.md`/`scaling-and-resilience.md`
cover intent and design (read those for _why_ and _what's planned_), this file
covers _what actually exists on disk right now_.

This doc can go stale as files move, get renamed, or get added. If a
referenced file or export doesn't exist, trust the live repo over this doc,
and treat the mismatch as a signal to refresh this file next time it's touched.

**Status: initial scaffold only — no business logic yet.** `api`, `web`, `shared` are empty-but-verified-runnable skeletons: `pnpm install`, `build`, `typecheck`, `lint`, `format`, both dev servers, and both production Docker images have all been run successfully against this exact scaffold. Fill this in for real once the domain model/API/UI land (see `docs/porting-notes.md` for the target layout), the same way `ubuntu-stories/docs/codebase-index.md` is maintained. Don't let it drift far behind the real tree — refresh it whenever a session touches a part of the repo this file doesn't yet describe accurately.

## Root

- `package.json` / `pnpm-workspace.yaml` / `turbo.json` — pnpm + Turborepo, matching `ubuntu-stories`. `typecheck` intentionally `dependsOn: ["^build"]` (not `^typecheck`) — `shared` only emits `dist/index.d.ts` via its `build` script, so dependents need that build to run first or their typecheck can't resolve `@transaction-dispute-portal/shared`'s types.
- `tsconfig.base.json`, `eslint.config.js`, `prettier.config.js` — shared across all three packages; no per-package lint/format config, same as `ubuntu-stories`. `eslint.config.js` ignores `web/server.mjs` (plain runtime `.mjs`, not part of any tsconfig program, so typescript-eslint's project service can't type-check it).
- `compose.yml` — Postgres + api + web dev stack, mirrors `ubuntu-stories/compose.yml` structure with `transaction-dispute-portal-*` naming. Builds api/web from their `Dockerfile.dev`.
- `env/development/.env.database.example` — Postgres creds template for `compose.yml`. Unlike `ubuntu-stories` (private repo, real `.env` files committed), this repo is going public — only `.env.example` files are ever committed; real `.env` files are gitignored.

## api (Fastify backend)

- `src/app.ts` — placeholder entry point: a bare Fastify instance with `/healthz` and `/readyz` routes, listening on `PORT` (default 8080). Verified booting via both `pnpm dev` and the built Docker image. Replace with the real `build()`/`app.ts` split (see `ubuntu-stories/api/app.ts` + `build.ts`) once auth/routes/drizzle land.
- `package.json` — scripts: `dev` (tsx watch), `build` (tsc), `start` (node dist), `typecheck`, `lint`, `clean`. No business dependencies yet (no fastify plugins, drizzle, better-auth) — added as each piece is ported per `docs/porting-notes.md`.
- `tsconfig.json` — extends root `tsconfig.base.json`; `rootDir`/`outDir` set explicitly (tsc errors without `rootDir` once `outDir` is set on a single-directory `include`).
- `.env.example` — `PORT`, `DATABASE_URL`, `BETTER_AUTH_SECRET`/`COOKIE_SECRET`/`INTERNAL_API_TOKEN` placeholders (generate real values with `openssl rand -base64 32`), rate-limit config. See `docs/api.md` for what `INTERNAL_API_TOKEN` gates.
- `Dockerfile` — production multi-stage (deps → build → prod-deps → runtime), non-root `node` user, no devDependencies or source in the final image. Verified: builds, and the running container answers `/healthz` on port 8080.
- `Dockerfile.dev` — mirrors `ubuntu-stories/api/Dockerfile.dev`: installs the whole workspace, runs `pnpm --filter @transaction-dispute-portal/api dev` with source bind-mounted via `compose.yml`.

## web (TanStack Start frontend)

- `src/routes/__root.tsx` / `src/routes/index.tsx` — placeholder route tree: a single index route rendering "Transactions Dispute Portal". Replace with real routes/loaders once the UI work starts. No UI kit/shadcn, forms, query client, or auth client yet — deliberately bare.
- `src/router.tsx` — TanStack Router instance wiring the generated route tree (`src/routeTree.gen.ts`, auto-generated by the router's Vite plugin on `dev`/`build` — don't hand-edit it).
- `server.mjs` — the production entry point. TanStack Start's `vite build` emits `dist/server/server.js` as a **bare Web-standard `fetch` handler with no attached runtime** (confirmed by inspecting the build output and the `@tanstack/react-start` package — it's meant to be wrapped by a hosting adapter, not run directly). `server.mjs` wraps it with `srvx` (already a transitive dependency, promoted to direct) to get an actual Node HTTP server: `serve({ fetch: handler.fetch, port, hostname: "0.0.0.0" })`. Running `node dist/server/server.js` directly does nothing and exits 0 silently — this tripped up the first pass at the production Dockerfile.
- `package.json` — scripts: `dev` (vite dev), `build` (vite build), `start` (`node server.mjs`), `typecheck`, `lint`, `clean`.
- `tsconfig.json` — extends root `tsconfig.base.json`; includes `server.mjs` for typecheck (excluded from eslint, see Root section).
- `.env.example` — `VITE_APP_NAME`, `VITE_API_URL`.
- `Dockerfile` — production multi-stage. The SSR build externalizes `react`/`react-dom` rather than bundling them (confirmed the hard way: the first build crashed at runtime with `ERR_MODULE_NOT_FOUND: react`), so unlike a typical "static output" frontend image, the runtime stage still needs `node_modules` (root + `web`) alongside `dist/` and `server.mjs`. Verified: builds, and the running container serves the SSR page on port 3000.
- `Dockerfile.dev` — mirrors `ubuntu-stories/web/Dockerfile.dev`.

## shared (types shared between api and web)

- `src/index.ts` — placeholder barrel export, currently empty of real domain types. `Transaction`/`Dispute`/`DisputeReason`/etc. (see `docs/domain-model.md`) land here once the schema is decided.
- `package.json` — `exports` points at `dist/index.js`/`dist/index.d.ts` (compiled), **not** `src/index.ts` directly like `ubuntu-stories/shared` does. `ubuntu-stories` never needs a production Node build (only `Dockerfile.dev`, always run via `tsx`/`vite`, both of which resolve `.ts` sources fine), so it never hit this; this repo's api ships a compiled `dist/app.js` run by plain `node` in production, which can't resolve a `.ts` import target. `dev` script (`tsc --watch`) keeps `dist/` fresh locally — `turbo dev` runs it in parallel with `api`/`web`'s own dev servers.
- `tsconfig.json` — extends root `tsconfig.base.json`; `rootDir`/`outDir` set explicitly (same `rootDir` requirement as `api`).
