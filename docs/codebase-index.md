# Codebase Index

A literal, per-file map of this repo — what lives where and what it's for — so a
session can jump straight to the right file instead of re-exploring the tree
with `find`/`grep` from scratch. This complements the other docs rather than
replacing them: `brief.md`/`api.md`/`domain-model.md`/`scaling-and-resilience.md`
cover intent and design (read those for _why_ and _what's planned_), this file
covers _what actually exists on disk right now_.

This doc can go stale as files move, get renamed, or get added. If a
referenced file or export doesn't exist, trust the live repo over this doc,
and treat the mismatch as a signal to refresh this file next time it's touched.

**Status: backend and frontend both feature-complete (auth + customer + admin flows, invites, account-security emails, a 44-test suite across both packages).** The full Drizzle schema (`docs/domain-model.md` entities + Better Auth tables), the Better Auth config, env validation, and email delivery all exist and are verified (migration applies clean on `postgres:18`, OTP / invite / new-device / email-change emails land in Mailpit end to end). The API request stack is real (`docs/decisions.md` #35): a `build()` factory (`src/build.ts`) split from `src/app.ts`, the full `middleware/` layer, the `modules/<name>/{route,service,type}` triad, and `route/index.ts` mounting modules under `shared`'s namespace prefixes. Modules: `check` (`/healthz`, `/readyz`), `authentication` (`POST /v1/auth/otp`, `/otp/verify`, `/sign-out`, `/change-email`, `/change-email/confirm`, `GET /v1/auth/session`, #37/#46/#50), `transaction` (`GET /v1/transactions`, `GET /v1/transactions/:transactionId`, customer-scoped, #39), `dispute` (`POST /v1/disputes`, `GET /v1/disputes`, `GET /v1/disputes/:disputeId`, `POST /v1/disputes/:disputeId/withdraw`, customer-scoped, #40/#45), `admin-dispute` (`GET /v1/admin/disputes`, `.../review`, `.../resolve`, admin-only, forward lifecycle, #41), `admin-invite` (`POST /v1/admin/invites`, `POST /v1/admin/invites/:token/accept`, invite-only admin signup, #44). All verified end to end against Postgres + Mailpit + ntfy. Data-access seam is `database/repository/` — per-table hand-written Drizzle functions taking an `Executor` (#36); customer reads exclude `user_id`/`resolved_by` via `getTableColumns` rest-spread (#43). Deterministic `db:seed` / `db:purge` scripts exist. **Environment is dev-only (#42):** one `compose.yml`, one `Dockerfile` per package, `docker compose up -d` is the whole stack, migrations run on api start; production is `docs/production-runbook.md`, not built. `web` is a real TanStack Start app now (#51): a session-gated route tree (`_authenticated`/`_unauthenticated` layouts), loader-driven data fetching throughout, one typed API client, live dispute-status toasts over ntfy SSE. A manual browser pass (sign in as customer and admin, open/withdraw/review/resolve a dispute) found and fixed two real bugs: every post-mutation UI update was silently no-op'ing (#52) and no dispute view showed what transaction it was about (#53); the admin review queue was also compacted into a table + modal (#54). The api's test suite runs against its own database (`transaction-dispute-test`), never the dev stack's (#55). A second, targeted regression pass across both roles found and fixed three more real gaps: the transaction page rendering the dispute form even with one already open instead of showing/linking it (and there was no way to see a transaction's *past* disputes at all — both closed by the same fetch, `GET /v1/disputes?transaction_id=...`, #56), and a cross-user 404 rendering as a generic client crash screen instead of the router's own not-found page — root-caused to `createServerFn`'s RPC boundary only round-tripping `notFound()`/`redirect()` intact, fixed with `rejectNotFound()` (#56). The deferred backend hardening items are catalogued in `docs/enhance-suggestion.md` ("Backend audit — 2026-09-06"). `pnpm install`, `turbo typecheck`/`lint`/`build`/`test` (44 tests: 36 api, 8 web), `docker compose up --wait` from a clean volume, and both manual browser passes above have all been run successfully. Don't let this file drift behind the real tree — refresh it whenever a session touches a part of the repo it doesn't yet describe accurately.

## Root

- `.github/workflows/build.yml` — the only workflow (`docs/decisions.md` #42). `on: [push, pull_request]`. Job `check`: `postgres:18-alpine` + `axllent/mailpit` service containers, job-level `env` (`DATABASE_URL`, `SMTP_*`, `MAILPIT_URL`), then `corepack enable` → `setup-node` (version from `.nvmrc`, pnpm store cached) → `pnpm install --frozen-lockfile` → `lint`/`typecheck`/`build` → `pnpm --filter …/api migrate` → `test` (the 33-test Vitest integration suite runs against the real Postgres + Mailpit, `docs/decisions.md` #47). Job `stack`: `docker compose up -d --build --wait --wait-timeout 300`, `curl /healthz`, `db:seed`, `docker compose down -v` — proves the clean-clone path CI-side. No `deploy.yml` / `migrate.yml` — a real deploy pipeline is `docs/production-runbook.md` §6, not built.
- `package.json` / `pnpm-workspace.yaml` / `turbo.json` — pnpm + Turborepo. `typecheck` intentionally `dependsOn: ["^build"]` (not `^typecheck`) — `shared` only emits `dist/index.d.ts` via its `build` script, so dependents need that build to run first or their typecheck can't resolve `@transaction-dispute-portal/shared`'s types.
- `tsconfig.base.json`, `eslint.config.js`, `prettier.config.js` — shared across all three packages; no per-package lint/format config. `eslint.config.js` ignores `web/server.mjs` (plain runtime `.mjs`, not part of any tsconfig program), sets `@typescript-eslint/no-unused-vars: { ignoreRestSiblings: true }` for the `getTableColumns` exclusion idiom (`docs/decisions.md` #43), and lists `api/{drizzle,vitest}.config.ts` under `allowDefaultProject` (the api test suite has its own `api/test/tsconfig.json`, auto-discovered by `projectService`).
- `compose.yml` — the one and only compose file (`docs/decisions.md` #42). Five services: `transaction-dispute-portal-{database,api,web,mailpit,ntfy}`. Dev-shaped throughout — whole-repo bind mount + `*-node_modules` volumes, CHOKIDAR polling, `tsx`/`vite` watch, published `5432`/`8080`/`3000`/`8025`/`8090`, 90s healthcheck `start_period`. The api `command:` is `pnpm … shared build && pnpm … api migrate && pnpm … api dev --host 0.0.0.0` (web: `shared build && web dev`) — `shared/dist` is gitignored and no image builds it, so the `shared build` step is what makes a clean `docker compose up` work at all (`docs/decisions.md` #42); then the schema is applied before serving. `db:seed` is a separate `docker compose exec …` one-shot. Mailpit alias `mailpit` (for `SMTP_HOST`), ntfy alias `ntfy` (for `NTFY_URL`), web UI on `8090`.
- `api/.env` / `web/.env` / `env/development/.env.database` — committed env files with **working local values** (`docs/decisions.md` #34/#42): `api/.env` has a real `DATABASE_URL` + `BETTER_AUTH_SECRET`/`COOKIE_SECRET` (freshly generated, local-only) + `NTFY_URL`; `env/development/.env.database` a real `POSTGRES_PASSWORD`; `web/.env` no secrets. `SMTP_*` points at Mailpit. No comments. `.gitignore` ignores only `*.env.local` (an optional personal override); `.dockerignore` keeps `.env*` globs (env is runtime, never baked).

## api (Fastify backend)

- `src/build.ts` — the `build(logger?)` factory (`docs/decisions.md` #35): constructs the Fastify instance (zod type provider, `trustProxy`, 1 MiB body limit, `genReqId` seeding the request id from `x-correlation-id` / `x-request-id`), runs `middlewares(app)` then `route(app)`, awaits `app.ready()`, returns the app **without** calling `listen()`. `logger` is optional so tests build a silent app.
- `src/app.ts` — the process entry point: calls `build(logger)`, wires `close-with-grace` (flip `shutdown.ts`'s flag, `app.close()`, log), then `app.listen({ port: env.PORT, host: "0.0.0.0" })`. Deliberately never imports `src/database/migrate.ts` — migrations are a separate step, not run on API boot (`docs/decisions.md` #24).
- `src/route/index.ts` — mounts every module plugin under its namespace prefix, resolved once from `shared`'s `API_URLS(env.API_VERSION)` (`HEALTH` → `""`, `AUTH` → `/v1/auth`, `CUSTOMER` → `/v1`, `ADMIN` → `/v1/admin`). Registers `check`, `authentication`, `transaction` + `dispute` (under `CUSTOMER`), `admin-dispute` + `admin-invite` (under `ADMIN`).
- `src/type/fastify.ts` — the `declare module "fastify"` augmentation: `FastifyInstance.{authenticate, authorize, connection}` and `FastifyRequest.{startTime, user, session}`.
- `src/middleware/index.ts` — `middlewares(app)`: registers helmet (CSP), `@fastify/cors` (from `env.CORS_ORIGIN`), `@fastify/rate-limit` (global, `env.RATE_LIMIT_*`), `@fastify/cookie` (`env.COOKIE_SECRET`), the zod validator/serializer compilers, `setErrorHandler(error)`, an inline `setNotFoundHandler` sending the shared 404 envelope, the timing/logging hooks, and the `authenticate` / `authorize` / `connection` decorators plus an `onClose` that closes the pool.
- `src/middleware/error.ts` — central error handler → shared envelope: `FST_ERR_VALIDATION` → 422 with `errors[]`, Better Auth `APIError` → 400, `DrizzleQueryError` whose `.cause` is a Postgres `23505` (unique violation) → 409 with per-constraint friendly copy from `CONFLICT_MESSAGE` (`dispute_open_per_transaction_uq_idx` → the one-open-dispute guard #40; `user_email_uq_idx` / `user_email_unique` → the invite-accept dup-account guard #44), any thrown 4xx `statusCode` → that status with the code reverse-looked-up from `HTTP_RESPONSE_CODE`, everything else → 500 (logged). No separate `not-found.ts` — that handler is a 3-line arrow in `middleware/index.ts`.
- `src/middleware/authenticate.ts` — `authenticate` preHandler: reads the Better Auth session (`auth.api.getSession`), 401 + redirect to `FRONTEND_URLS.SIGN_IN` if absent, else attaches `request.user` (`UserModelSelect`) and `request.session` (`SessionModelSelect`).
- `src/middleware/authorize.ts` — `authorize(role | role[])` → a preHandler that 403s unless `request.user.role` is in the allow-list.
- `src/middleware/logging.ts` — `onRequestTimerHook` (stamp `startTime`, echo `x-correlation-id`) and `onResponseLoggingHook` (one structured line per request with method/route/status/`durationMs`/`correlationId`; `/healthz` + `/readyz` excluded).
- `src/lib/logger.ts` — the Pino instance: `pino-pretty` transport in development, plain JSON in test/production, level from `env.LOG_LEVEL`. No custom level set (`docs/decisions.md` #35).
- `src/lib/shutdown.ts` — a module-level boolean with `setShuttingDown` / `isShuttingDown`; `check`'s probes read it, `app.ts` flips it on signal.
- `src/lib/authentication.ts` — thin wrappers over the Better Auth server API (`sendSignInOtp`, `verifySignInOtp`, `signOut`, `requestEmailChange` → `auth.api.changeEmail`, `confirmEmailChange` → `auth.api.verifyEmail`), converting Fastify headers with `fromNodeHeaders` and returning Better Auth's raw `Response` where the caller needs the cookies. Called only by `modules/authentication/service.ts` (`docs/decisions.md` #37/#46).
- `src/lib/security-notifications.ts` — `alertOnNewDeviceLogin(session)`: called from `lib/auth.ts`'s `databaseHooks.session.create.after`. Skips if no `user_agent`; else `repository/session.ts` `hasKnownDeviceSession` (same `user_id` + `user_agent`, different session id) → if unseen, `findUserById` then `sendEmail(buildNewDeviceLoginEmail({ …, signInUrl: env.FRONTEND_URL + FRONTEND_URLS.SIGN_IN }))`. Best-effort, `void`-ed, never awaited into the login response (`docs/auth.md` §3, `docs/decisions.md` #46). Imports `connection` directly (no request context in a BA hook).
- `src/modules/check/{route,service,type}.ts` — `GET /healthz` (liveness — 503 while draining) and `GET /readyz` (readiness — 503 while draining or if `select 1` doesn't answer within 2s; `docs/decisions.md` #35). Responses use `healthzResponseSchema` / `readyzResponseSchema`.
- `src/modules/authentication/{route,service,type}.ts` — `GET /v1/auth/session` (`authenticate` only, no role check — the signed-in user for client route guards, #50), `POST /v1/auth/otp` (send a code; identical response whether or not the account exists; writes `OTP_REQUESTED`; `OTP.MAX_ATTEMPTS`/min per IP), `POST /v1/auth/otp/verify` (exchange code for a session, forward `Set-Cookie`; writes `LOGIN_SUCCESS` / `LOGIN_FAILURE` / `OTP_LOCKED`; `2 × MAX_ATTEMPTS`/min), `POST /v1/auth/change-email` (`{ newEmail }`, `authenticate`; wraps BA `changeEmail` — approval link to the *current* address first; anti-probing 200 copy; writes `EMAIL_CHANGE_REQUESTED`), `POST /v1/auth/change-email/confirm` (`{ token }`, no auth; applies one step; bad/expired token → 401), `POST /v1/auth/sign-out` (unconditional). All go through `lib/authentication.ts` + `repository/auth-audit-log.ts` (`docs/decisions.md` #37/#46).
- `src/modules/admin-invite/{route,service,type}.ts` — invite-only admin signup (`docs/decisions.md` #44). `POST /v1/admin/invites` (`authenticate` + `authorize(ADMIN)`; `{ email }`; `409` if an account exists; `randomBytes(32)` hex token, `expires_at = now + ADMIN_INVITE_EXPIRY_HOURS`, real invite email; wire response omits the token). `POST /v1/admin/invites/:token/accept` (no auth — the invitee has no session; `{ name }`, email from the invite; missing token → `404`, used/expired → `409`; one transaction: `acceptAdminInvite` guarded `UPDATE` → `createUser({ role: ADMIN, email_verified: true })`; `redirectUrl: FRONTEND_URLS.SIGN_IN`). Own rate limit (`OTP.MAX_ATTEMPTS * 2`).
- `src/modules/transaction/{route,service,type}.ts` — `GET /v1/transactions` (a page of the caller's own transactions, ordered on `transacted_at`; query `from` / `to` / `order` / `page` / `limit`) and `GET /v1/transactions/:transactionId` (one transaction, `404` if it isn't the caller's or doesn't exist, `422` if the id is malformed). Both `preHandler: [authenticate, authorize(CUSTOMER)]`. Service converts `Date` columns to ISO strings; the owner filter lives in the `repository/transaction.ts` query, not a post-fetch check (`docs/decisions.md` #39).
- `src/modules/dispute/{route,service,type}.ts` — customer-scoped, `preHandler: [authenticate, authorize(CUSTOMER)]`. `POST /v1/disputes` (open a dispute on one of the caller's own transactions — body `{ transactionId, reason, description }`; ownership miss → `404` per #39; insert + first `dispute_audit_log` row in one `connection.transaction()`; the one-open-dispute rule is the partial unique index + the global 409 handler, no pre-check — `docs/decisions.md` #40). `GET /v1/disputes` (a page of the caller's disputes, optional `status` and `transaction_id` filters — the latter powers the transaction detail page's open-dispute check + history list, #56 — `order`/`page`/`limit`). `GET /v1/disputes/:disputeId` (one, scoped; other-user/missing → `404`, malformed → `422`). `POST /v1/disputes/:disputeId/withdraw` (close the caller's own open dispute as `WITHDRAWN`; whole handler in one transaction — `findUserDisputeById(..., { lockForUpdate: true })` for a `404`/`409` distinction and an accurate audit `from_status`, then the guarded `withdrawDispute` `UPDATE`; `docs/decisions.md` #45, audit A2). Open/terminal status checks use `shared`'s `isOpenDisputeStatus` (#49). Wire schema omits `user_id`/`resolved_by`; every response nests the disputed transaction's `merchant_name`/`amount_cents`/`transacted_at` (#53).
- `src/modules/admin-dispute/{route,service,type}.ts` — admin-only, `preHandler: [authenticate, authorize(ADMIN)]` (a customer session → `403`). `GET /v1/admin/disputes` (every customer's disputes for the review queue, optional `status` filter; wire shape = customer's + `user_id`). `POST /v1/admin/disputes/:disputeId/review` (`SUBMITTED → UNDER_REVIEW`; idempotent `200` no-op if already under review; audit row + ntfy publish). `POST /v1/admin/disputes/:disputeId/resolve` (body `{ resolution: RESOLVED|REJECTED, note }`; requires `UNDER_REVIEW` — a still-`SUBMITTED` dispute → `409`; updates `status`/`resolution_note`/`resolved_by`/`resolved_at` + audit row + ntfy, one transaction). Both transitions guard the from-status inside the `UPDATE … WHERE` so concurrent calls collapse to one write (`docs/decisions.md` #41). Every response nests the disputed transaction's summary too, merged in from the pre-write `findDisputeById` read (#53).
- `src/database/` — everything database-related lives together here (schema, migrations, connection, migration runner, repository, seed/purge), unlike Ubuntu Stories' split between `src/drizzle/` and `src/lib/database.ts` — see `docs/decisions.md` #24 for why.
- `src/database/executor.ts` — the `Executor` type (`typeof connection | Transaction`): what every `repository/` function takes as its first argument so the caller owns transaction scope (`docs/decisions.md` #36).
- `src/database/repository/*.ts` — one file per table of plain hand-written Drizzle functions, re-exported from `index.ts`; modules import from here, never from each other (`docs/decisions.md` #36). Pagination totals use `executor.$count(table, where)`. `auth-audit-log.ts` (`recordAuthEvent`; `clamp`s ip/user-agent to 255). `user.ts` (`findUserByEmail` / `findUserById` — full row; `createUser` — `email_verified: true`, sole caller is invite acceptance). `session.ts` (`hasKnownDeviceSession` — same `user_id` + `user_agent`, excluding one session id). `admin-invite.ts` (`createAdminInvite`, `findAdminInviteByToken`, `acceptAdminInvite` — guarded `UPDATE … WHERE token = ? AND accepted_at IS NULL AND expires_at > now()`, #4/#44). `transaction.ts` (`findTransactionsByUser`, `findUserTransactionById` — scoped by `id` **and** `user_id`, #39). `dispute.ts` (`findDisputesByUser` / `findUserDisputeById` — customer, scoped, columns via `getTableColumns` rest-spread excluding `user_id`/`resolved_by`, #43; both `innerJoin` `TransactionModel` and select a nested `transaction: TRANSACTION_SUMMARY_COLUMNS`, #53; `findDisputesByUser` takes an optional `transactionId` filter, #56; `findUserDisputeById` takes an optional `{ lockForUpdate }` for `SELECT … FOR UPDATE`, #45; `findDisputesForReview` / `findDisputeById` — admin, full row, same transaction join; `markDisputeUnderReview` / `resolveDispute` / `withdrawDispute` — the from-status is in the `UPDATE … WHERE`, empty `RETURNING` is the caller's 409, #41/#45, no join (an `UPDATE … RETURNING` can't join — the service layer merges in the transaction from a prior read instead, #53); `createDispute`, same). `dispute-audit-log.ts` (`recordDisputeStatusChange` — one row per transition: actor, from/to status, note).
- `src/database/seed.ts` — `pnpm --filter …/api db:seed`: deterministic (`faker.seed`) seed — truncates the data tables, then inserts ~31 users (1 admin on Nolan's email, a long-history `customer@example.com`, a no-disputes `newcomer@example.com`, ~28 faker customers), one `KNOWN_DEVICE_USER_AGENT` session each for the admin + demo customer (so the new-device alert is quiet on a known device, `docs/auth.md` §3), ~4.6k ZAR-cent transactions with SA merchant names spread over 14 months (`date-fns` `subMonths`), ~260 disputes across every status/reason (including `WITHDRAWN`, ~7%) on distinct transactions, and one `dispute_audit_log` row per status transition (a `SUBMITTED → WITHDRAWN` row for withdrawn ones). Own single (`max: 1`) connection, reads `process.env.DATABASE_URL` directly like `migrate.ts`.
- `src/database/purge.ts` — `pnpm --filter …/api db:purge`: `TRUNCATE ... RESTART IDENTITY CASCADE` every `public` table except drizzle's migration ledger. Leaves the schema intact.
- `src/database/schema/*.ts` — one table per file, Ubuntu Stories house style (`docs/decisions.md` #28): `user`, `session`, `account`, `verification` (Better Auth tables, our columns + `fields` maps in `lib/auth.ts`); `transaction`, `dispute`, `dispute-audit-log`, `admin-invite`, `auth-audit-log` (domain). Each exports `XxxModel` + `XxxModelInsert`/`Select`/`UniqueWhere` types; `pgEnum`s (`userRole`, `disputeStatus` incl. `WITHDRAWN`, `disputeReason`, `authEvent` incl. `EMAIL_CHANGE_REQUESTED`) built from `shared/src/constant.ts` SCREAMING_SNAKE constants (#30). Every PK is `uuid` defaulting to Postgres 18 native `sql\`uuidv7()\`` (#29). `user.name` is `NOT NULL`. `dispute.ts` carries the partial unique index for the one-open-dispute guard (#4/#28/#40) and a `resolved_by` FK to `user`. `admin-invite.ts` has a unique `token`, an `invited_by` FK to `user`, and `email` / `invited_by` / `updated_at` indexes (#44). `relations.ts` holds every `relations()` call centrally.
- `src/database/schema/index.ts` — barrel: re-exports all nine table files then `relations.js`. `drizzle-kit generate` reads this.
- `src/database/migrations/` — generated SQL, committed. `0000_minor_morlun.sql` creates all nine tables + enums + indexes; `meta/` snapshots (`_journal.json` has one entry). Single migration kept, regenerated in place each time the schema changed pre-deployment (`user.name` → `NOT NULL`; `disputeStatus` gained `WITHDRAWN`; `authEvent` gained `EMAIL_CHANGE_REQUESTED`) rather than stacking `0001`, `0002` — the dev DB is always re-created (`docker compose down -v`). `drizzle-kit check` clean; applies clean on `postgres:18`. `compose.yml` runs the migrate runner on api start (#42).
- `src/database/config.ts` — the app's pooled `postgres-js` connection + `drizzle()` instance (`connection`), for query code once routes exist. `globalThis`-cached singleton (same pattern as Ubuntu Stories) — `tsx watch` hot-reloads this module on every save, and a naive `postgres()` call here would leak a connection per reload. Throws at import time if `DATABASE_URL` is unset.
- `src/database/migrate.ts` — standalone migration runner, its own single (`max: 1`) short-lived connection (deliberately not `config.ts`'s pool, `onnotice` silenced), applies SQL from `src/database/migrations` via `drizzle-orm`'s runtime migrator and exits. Never imported by `app.ts`. Run via `pnpm --filter @transaction-dispute-portal/api migrate` — `compose.yml` chains it before the dev server on api start (`docs/decisions.md` #42); production runs it as a gated pre-deploy step (`docs/production-runbook.md` §3). Custom runtime script rather than `npx drizzle-kit migrate` so it works with no devDependencies present (`docs/decisions.md` #24).
- `src/lib/env.ts` — zod-validated `process.env` singleton (`docs/decisions.md` #28): parsed once, cached, `process.exit(1)` with a per-key report on failure. Includes `NTFY_URL` (default `http://ntfy`). Every module imports the typed `env`, never `process.env`.
- `src/lib/auth.ts` — the Better Auth instance (`docs/decisions.md` #21/#28/#46): `drizzleAdapter` over `config.ts`'s `connection` with the four Better Auth tables mapped field-by-field to our snake_case columns; `emailAndPassword` off; `emailOTP` plugin only (length / hashed / `disableSignUp` / expiry / attempts all from `shared`'s `OTP` constant) with `sendVerificationOTP` calling `mailer.ts`; `emailVerification.sendVerificationEmail` + `user.changeEmail.{enabled, sendChangeEmailConfirmation}` wire the two-step email-change flow (`email-verification.ts` / `email-change-approval.ts` builders, `EMAIL_CHANGE_TOKEN_EXPIRY_MINUTES`); `databaseHooks.session.create.after` → `alertOnNewDeviceLogin` (`void`-ed); `basePath` from `API_URLS(env.API_VERSION).AUTH`; `additionalFields.role` typed as `Object.values(USER_ROLE)` with `input: false` + `defaultValue: CUSTOMER`, so Better Auth infers `user.role` as `"ADMIN" | "CUSTOMER"` and `authenticate.ts` needs no cast/parse/fallback; `advanced.database.generateId` → `util.ts` v7; Better Auth's own `rateLimit` disabled (#35).
- `src/lib/mailer.ts` — `nodemailer` transport from `env` + `sendEmail({ to, subject, html })` that logs-and-swallows failures (Better Auth "don't await OTP" timing advice). One file, not Ubuntu Stories' transport/mailer split (`docs/decisions.md` #31).
- `src/lib/notifier.ts` — `publishDisputeUpdate(userId, status)`: a fire-and-forget `fetch` POST to `${env.NTFY_URL}/dispute-updates-${userId}` with the new status as the body, `AbortSignal.timeout(2000)`, failures logged not thrown (same posture as `mailer.ts`). Called by `modules/admin-dispute` on `review` / `resolve` (`docs/notifications.md`, `docs/decisions.md` #41).
- `src/lib/util.ts` — `generateUuid()` (`uuid` package v7, for Better Auth's app-side ID generation) and `withTimeout(promise, ms)` (used by `readyz`'s DB probe).
- `src/email/*.ts` — plain builders returning `EmailContent` (`{ to, subject, html }`), no registry (`docs/decisions.md` #31). `otp-email-sign-in-request.ts` (sign-in code), `admin-invite.ts` (invite link, #44), `new-device-login.ts` (`docs/auth.md` §3 — takes an absolute `signInUrl`, audit A1), `email-change-approval.ts` (approval link to the *old* address), `email-verification.ts` (verification link to the *new* address).

## web (TanStack Start frontend)

**A real app now (`docs/decisions.md` #51):** session-gated route tree, TanStack Router loaders + TanStack Query for every fetch (no `useEffect`), one axios client with a single normalized error type, hand-picked shadcn-style UI primitives, react-hook-form + zod forms, live dispute-status toasts over ntfy SSE. Two manual browser passes end to end found and fixed: a post-mutation UI staleness bug (#52), a missing-transaction-context gap (#53), a UI density fix to the admin review queue (#54), a transaction page that rendered its dispute form even with one already open plus no way to see a transaction's dispute history (both #56), and cross-user 404s rendering as a generic crash screen instead of the router's not-found page — `rejectNotFound()` converts a 404 into the framework's `notFound()` before it crosses the `createServerFn` RPC boundary, which only round-trips `notFound()`/`redirect()` intact (#56). Typecheck/lint/`vitest run` all pass (8 tests).

- `src/routes/__root.tsx` — the root layout (`<html>`/`<head>`/`<body>`, `Toaster`, page `<title>` = `APP_NAME`). `beforeLoad` seeds `RouterContext.user` (`AuthSession | null`) by `ensureQueryData`-ing `GET /v1/auth/session` (`api/auth.ts`'s `sessionRequest`) once per navigation root — the one place the whole app learns who's signed in (#50/#51).
- `src/routes/_unauthenticated.tsx` / `src/routes/_unauthenticated/sign-in.tsx` — the signed-out layout and the two-step OTP sign-in form (request a code, then verify it), `react-hook-form` + `zodResolver` over `shared`'s `authOtpRequestBodySchema`/`authOtpVerifyBodySchema`.
- `src/routes/_authenticated.tsx` — the signed-in layout (`Navigation` + `useDisputeNotifications` for customers). `beforeLoad` redirects to sign-in with no session, then splits by role: a customer under `/admin` → `/transactions`, an admin outside `/admin` → `/admin`, except the shared `/account` prefix both roles can reach.

The detail loader also fetches this transaction's disputes (`GET /v1/disputes?transaction_id=...`, #56): an open one renders as a "View dispute" link instead of the form; any closed ones render as a "Dispute history" list underneath (`dispute-form.tsx` only mounts when there's nothing open).

- `src/routes/admin/invite.tsx` — **outside** `_authenticated`: the admin-invite accept page (`{ name }` + the URL's `token` → `acceptAdminInvite`, #44), then redirects to sign-in.
