session can jump straight to the right file instead of re-exploring the tree
with `find`/`grep` from scratch. This complements the other docs rather than
replacing them: `brief.md`/`api.md`/`domain-model.md`/`scaling-and-resilience.md`

referenced file or export doesn't exist, trust the live repo over this doc,
and treat the mismatch as a signal to refresh this file next time it's touched.

**Status: full API surface wired (auth + customer + admin dispute flows); UI and tests still to come.** The full Drizzle schema (`docs/domain-model.md` entities + Better Auth tables), the Better Auth config, env validation, and OTP email delivery all exist and are verified (migration applies clean on `postgres:18`, an OTP email lands in Mailpit end to end). ## Root

- `.github/workflows/build.yml` — the only workflow (`docs/decisions.md` #42). `on: [push, pull_request]`. Job `check`: `corepack enable` → `setup-node` (version from `.nvmrc`, pnpm store cached) → `pnpm install --frozen-lockfile` → `lint`/`typecheck`/`build`/`test`. Job `stack`: `docker compose up -d --build --wait --wait-timeout 300`, `curl /healthz`, `db:seed`, `docker compose down -v` — proves the clean-clone path CI-side. `pnpm test` currently succeeds trivially — no package defines a `test` script yet; this starts failing loudly the moment Vitest tests are added without wiring, which is the intent. No `deploy.yml` / `migrate.yml` — a real deploy pipeline is `docs/production-runbook.md` §6, not built.
- `package.json` / `pnpm-workspace.yaml` / `turbo.json` — pnpm + Turborepo. `typecheck` intentionally `dependsOn: ["^build"]` (not `^typecheck`) — `shared` only emits `dist/index.d.ts` via its `build` script, so dependents need that build to run first or their typecheck can't resolve `@transaction-dispute-portal/shared`'s types.
- `tsconfig.base.json`, `eslint.config.js`, `prettier.config.js` — shared across all three packages; no per-package lint/format config. `eslint.config.js` ignores `web/server.mjs` (plain runtime `.mjs`, not part of any tsconfig program) and sets `@typescript-eslint/no-unused-vars: { ignoreRestSiblings: true }` for the `getTableColumns` exclusion idiom (`docs/decisions.md` #43).
- `compose.yml` — the one and only compose file (`docs/decisions.md` #42). Five services: `transaction-dispute-portal-{database,api,web,mailpit,ntfy}`. Dev-shaped throughout — whole-repo bind mount + `*-node_modules` volumes, CHOKIDAR polling, `tsx`/`vite` watch, published `5432`/`8080`/`3000`/`8025`/`8090`, 90s healthcheck `start_period`. The api `command:` is `pnpm … migrate && pnpm … dev --host 0.0.0.0`, so `docker compose up -d` on a clean volume applies the schema before serving. `db:seed` is a separate `docker compose exec …` one-shot. Mailpit alias `mailpit` (for `SMTP_HOST`), ntfy alias `ntfy` (for `NTFY_URL`), web UI on `8090`.
- `api/.env` / `web/.env` / `env/development/.env.database` — committed env files with **working local values** (`docs/decisions.md` #34/#42): `api/.env` has a real `DATABASE_URL` + `BETTER_AUTH_SECRET`/`COOKIE_SECRET` (freshly generated, local-only) + `NTFY_URL`; `env/development/.env.database` a real `POSTGRES_PASSWORD`; `web/.env` no secrets. `SMTP_*` points at Mailpit. No comments. `.gitignore` ignores only `*.env.local` (an optional personal override); `.dockerignore` keeps `.env*` globs (env is runtime, never baked).

## api (Fastify backend)

- `src/build.ts` — the `build(logger?)` factory (`docs/decisions.md` #35): constructs the Fastify instance (zod type provider, `trustProxy`, 1 MiB body limit, `genReqId` seeding the request id from `x-correlation-id` / `x-request-id`), runs `middlewares(app)` then `route(app)`, awaits `app.ready()`, returns the app **without** calling `listen()`. `logger` is optional so tests build a silent app.
- `src/app.ts` — the process entry point: calls `build(logger)`, wires `close-with-grace` (flip `shutdown.ts`'s flag, `app.close()`, log), then `app.listen({ port: env.PORT, host: "0.0.0.0" })`. Deliberately never imports `src/database/migrate.ts` — migrations are a separate step, not run on API boot (`docs/decisions.md` #24).
- `src/route/index.ts` — mounts every module plugin under its namespace prefix, resolved once from `shared`'s `API_URLS(env.API_VERSION)` (`HEALTH` → `""`, `AUTH` → `/v1/auth`, `CUSTOMER` → `/v1`, `ADMIN` → `/v1/admin`). Registers `check`, `authentication`, `transaction` + `dispute` (under `CUSTOMER`), `admin-dispute` (under `ADMIN`).
- `src/type/fastify.ts` — the `declare module "fastify"` augmentation: `FastifyInstance.{authenticate, authorize, connection}` and `FastifyRequest.{startTime, user, session}`.
- `src/middleware/index.ts` — `middlewares(app)`: registers helmet (CSP), `@fastify/cors` (from `env.CORS_ORIGIN`), `@fastify/rate-limit` (global, `env.RATE_LIMIT_*`), `@fastify/cookie` (`env.COOKIE_SECRET`), the zod validator/serializer compilers, `setErrorHandler(error)`, an inline `setNotFoundHandler` sending the shared 404 envelope, the timing/logging hooks, and the `authenticate` / `authorize` / `connection` decorators plus an `onClose` that closes the pool.
- `src/middleware/error.ts` — central error handler → shared envelope: `FST_ERR_VALIDATION` → 422 with `errors[]`, Better Auth `APIError` → 400, `DrizzleQueryError` whose `.cause` is a Postgres `23505` (unique violation) → 409 with per-constraint friendly copy (`docs/decisions.md` #40 — the one-open-dispute guard surfaces here), any thrown 4xx `statusCode` → that status with the code reverse-looked-up from `HTTP_RESPONSE_CODE`, everything else → 500 (logged). No separate `not-found.ts` — that handler is a 3-line arrow in `middleware/index.ts`.
- `src/middleware/authenticate.ts` — `authenticate` preHandler: reads the Better Auth session (`auth.api.getSession`), 401 + redirect to `FRONTEND_URLS.SIGN_IN` if absent, else attaches `request.user` (`UserModelSelect`) and `request.session` (`SessionModelSelect`).
- `src/middleware/authorize.ts` — `authorize(role | role[])` → a preHandler that 403s unless `request.user.role` is in the allow-list.
- `src/middleware/logging.ts` — `onRequestTimerHook` (stamp `startTime`, echo `x-correlation-id`) and `onResponseLoggingHook` (one structured line per request with method/route/status/`durationMs`/`correlationId`; `/healthz` + `/readyz` excluded).
- `src/lib/logger.ts` — the Pino instance: `pino-pretty` transport in development, plain JSON in test/production, level from `env.LOG_LEVEL`. No custom level set (`docs/decisions.md` #35).
- `src/lib/shutdown.ts` — a module-level boolean with `setShuttingDown` / `isShuttingDown`; `check`'s probes read it, `app.ts` flips it on signal.
- `src/lib/authentication.ts` — thin wrappers over the Better Auth server API (`sendSignInOtp`, `verifySignInOtp`, `signOut`), converting Fastify headers with `fromNodeHeaders` and returning Better Auth's raw `Response` where the caller needs the cookies. Called only by `modules/authentication/service.ts` (`docs/decisions.md` #37).
- `src/modules/check/{route,service,type}.ts` — `GET /healthz` (liveness — 503 while draining) and `GET /readyz` (readiness — 503 while draining or if `select 1` doesn't answer within 2s; `docs/decisions.md` #35). Responses use `healthzResponseSchema` / `readyzResponseSchema`.
- `src/modules/authentication/{route,service,type}.ts` — `POST /v1/auth/otp` (send a code; identical response whether or not the account exists; writes `OTP_REQUESTED`; `OTP.MAX_ATTEMPTS`/min per IP), `POST /v1/auth/otp/verify` (exchange code for a session, forward `Set-Cookie`; writes `LOGIN_SUCCESS` / `LOGIN_FAILURE` / `OTP_LOCKED`; `2 × MAX_ATTEMPTS`/min), `POST /v1/auth/sign-out` (unconditional). All go through `lib/authentication.ts` + `repository/auth-audit-log.ts` (`docs/decisions.md` #37).
- `src/modules/transaction/{route,service,type}.ts` — `GET /v1/transactions` (a page of the caller's own transactions, ordered on `transacted_at`; query `from` / `to` / `order` / `page` / `limit`) and `GET /v1/transactions/:transactionId` (one transaction, `404` if it isn't the caller's or doesn't exist, `422` if the id is malformed). Both `preHandler: [authenticate, authorize(CUSTOMER)]`. Service converts `Date` columns to ISO strings; the owner filter lives in the `repository/transaction.ts` query, not a post-fetch check (`docs/decisions.md` #39).
- `src/modules/dispute/{route,service,type}.ts` — customer-scoped, `preHandler: [authenticate, authorize(CUSTOMER)]`. `POST /v1/disputes` (open a dispute on one of the caller's own transactions — body `{ transactionId, reason, description }`; ownership miss → `404` per #39; insert + first `dispute_audit_log` row in one `connection.transaction()`; the one-open-dispute rule is the partial unique index + the global 409 handler, no pre-check — `docs/decisions.md` #40). `GET /v1/disputes` (a page of the caller's disputes, optional `status` filter, `order`/`page`/`limit`). `GET /v1/disputes/:disputeId` (one, scoped; other-user/missing → `404`, malformed → `422`). Wire schema omits `user_id`/`resolved_by`.
- `src/modules/admin-dispute/{route,service,type}.ts` — admin-only, `preHandler: [authenticate, authorize(ADMIN)]` (a customer session → `403`). `GET /v1/admin/disputes` (every customer's disputes for the review queue, optional `status` filter; wire shape = customer's + `user_id`). `POST /v1/admin/disputes/:disputeId/review` (`SUBMITTED → UNDER_REVIEW`; idempotent `200` no-op if already under review; audit row + ntfy publish). `POST /v1/admin/disputes/:disputeId/resolve` (body `{ resolution: RESOLVED|REJECTED, note }`; requires `UNDER_REVIEW` — a still-`SUBMITTED` dispute → `409`; updates `status`/`resolution_note`/`resolved_by`/`resolved_at` + audit row + ntfy, one transaction). Both transitions guard the from-status inside the `UPDATE … WHERE` so concurrent calls collapse to one write (`docs/decisions.md` #41).
- `src/database/` — everything database-related lives together here (schema, migrations, connection, migration runner, repository, seed/purge), unlike Ubuntu Stories' split between `src/drizzle/` and `src/lib/database.ts` — see `docs/decisions.md` #24 for why.
- `src/database/executor.ts` — the `Executor` type (`typeof connection | Transaction`): what every `repository/` function takes as its first argument so the caller owns transaction scope (`docs/decisions.md` #36).
- `src/database/repository/*.ts` — one file per table of plain hand-written Drizzle functions, re-exported from `index.ts`; modules import from here, never from each other (`docs/decisions.md` #36). Pagination totals use `executor.$count(table, where)`. `auth-audit-log.ts` (`recordAuthEvent`). `transaction.ts` (`findTransactionsByUser`, `findUserTransactionById` — scoped by `id` **and** `user_id`, #39). `dispute.ts` (`findDisputesByUser` / `findUserDisputeById` — customer, scoped, columns via `getTableColumns` rest-spread excluding `user_id`/`resolved_by`, #43; `findDisputesForReview` / `findDisputeById` — admin, full row; `markDisputeUnderReview` / `resolveDispute` — the from-status is in the `UPDATE … WHERE`, empty `RETURNING` is the caller's 409, #41; `createDispute`). `dispute-audit-log.ts` (`recordDisputeStatusChange` — one row per transition: actor, from/to status, note).
- `src/database/seed.ts` — `pnpm --filter …/api db:seed`: deterministic (`faker.seed`) seed — truncates the data tables, then inserts ~31 users (1 admin on Nolan's email, a long-history `customer@example.com`, a no-disputes `newcomer@example.com`, ~28 faker customers), ~4.6k ZAR-cent transactions with SA merchant names spread over 14 months (`date-fns` `subMonths`), ~260 disputes across every status/reason on distinct transactions, and one `dispute_audit_log` row per status transition. Own single (`max: 1`) connection, reads `process.env.DATABASE_URL` directly like `migrate.ts`.
- `src/database/purge.ts` — `pnpm --filter …/api db:purge`: `TRUNCATE ... RESTART IDENTITY CASCADE` every `public` table except drizzle's migration ledger. Leaves the schema intact.
- `src/database/schema/*.ts` — one table per file, Ubuntu Stories house style (`docs/decisions.md` #28): `user`, `session`, `account`, `verification` (Better Auth tables, our columns + `fields` maps in `lib/auth.ts`); `transaction`, `dispute`, `dispute-audit-log`, `admin-invite`, `auth-audit-log` (domain). Each exports `XxxModel` + `XxxModelInsert`/`Select`/`UniqueWhere` types; `pgEnum`s (`userRole`, `disputeStatus`, `disputeReason`, `authEvent`) built from `shared/src/constant.ts` SCREAMING_SNAKE constants (#30). Every PK is `uuid` defaulting to Postgres 18 native `sql\`uuidv7()\`` (#29). `user.name` is `NOT NULL`. `dispute.ts` carries the partial unique index for the one-open-dispute guard (#4/#28/#40) and a `resolved_by` FK to `user`. `relations.ts` holds every `relations()` call centrally.
- `src/database/schema/index.ts` — barrel: re-exports all nine table files then `relations.js`. `drizzle-kit generate` reads this.
- `src/database/migrations/` — generated SQL, committed. `0000_next_peter_quill.sql` creates all nine tables + enums + indexes; `meta/` snapshots. Single migration kept, regenerated in place when the schema changed pre-deployment (`user.name` → `NOT NULL`) rather than adding `0001` — the dev DB is always re-created. `drizzle-kit check` clean; applies clean on `postgres:18` (idempotent re-run verified). `compose.yml` runs the migrate runner on api start (#42).
- `src/database/config.ts` — the app's pooled `postgres-js` connection + `drizzle()` instance (`connection`), for query code once routes exist. `globalThis`-cached singleton (same pattern as Ubuntu Stories) — `tsx watch` hot-reloads this module on every save, and a naive `postgres()` call here would leak a connection per reload. Throws at import time if `DATABASE_URL` is unset.
- `src/database/migrate.ts` — standalone migration runner, its own single (`max: 1`) short-lived connection (deliberately not `config.ts`'s pool, `onnotice` silenced), applies SQL from `src/database/migrations` via `drizzle-orm`'s runtime migrator and exits. Never imported by `app.ts`. Run via `pnpm --filter @transaction-dispute-portal/api migrate` — `compose.yml` chains it before the dev server on api start (`docs/decisions.md` #42); production runs it as a gated pre-deploy step (`docs/production-runbook.md` §3). Custom runtime script rather than `npx drizzle-kit migrate` so it works with no devDependencies present (`docs/decisions.md` #24).
- `src/lib/env.ts` — zod-validated `process.env` singleton (`docs/decisions.md` #28): parsed once, cached, `process.exit(1)` with a per-key report on failure. Includes `NTFY_URL` (default `http://ntfy`). Every module imports the typed `env`, never `process.env`.
- `src/lib/auth.ts` — the Better Auth instance (`docs/decisions.md` #21/#28): `drizzleAdapter` over `config.ts`'s `connection` with the four Better Auth tables mapped field-by-field to our snake_case columns; `emailAndPassword` off; `emailOTP` plugin only (length / hashed / `disableSignUp` / expiry / attempts all from `shared`'s `OTP` constant) with `sendVerificationOTP` calling `mailer.ts`; `basePath` from `API_URLS(env.API_VERSION).AUTH`; `additionalFields.role` typed as `Object.values(USER_ROLE)` with `input: false` + `defaultValue: CUSTOMER`, so Better Auth infers `user.role` as `"ADMIN" | "CUSTOMER"` and `authenticate.ts` needs no cast/parse/fallback; `advanced.database.generateId` → `util.ts` v7; Better Auth's own `rateLimit` disabled (#35).
- `src/lib/mailer.ts` — `nodemailer` transport from `env` + `sendEmail({ to, subject, html })` that logs-and-swallows failures (Better Auth "don't await OTP" timing advice). One file, not Ubuntu Stories' transport/mailer split (`docs/decisions.md` #31).
- `src/lib/notifier.ts` — `publishDisputeUpdate(userId, status)`: a fire-and-forget `fetch` POST to `${env.NTFY_URL}/dispute-updates-${userId}` with the new status as the body, `AbortSignal.timeout(2000)`, failures logged not thrown (same posture as `mailer.ts`). Called by `modules/admin-dispute` on `review` / `resolve` (`docs/notifications.md`, `docs/decisions.md` #41).
- `src/lib/util.ts` — `generateUuid()` (`uuid` package v7, for Better Auth's app-side ID generation) and `withTimeout(promise, ms)` (used by `readyz`'s DB probe).
- `src/email/otp-email-sign-in-request.ts` — builder returning `{ to, subject, html }` for the sign-in OTP email. The only template so far; more (recovery/invite, `docs/auth.md` §3) land here as plain builders, no registry (`docs/decisions.md` #31).
- `drizzle.config.ts` — `drizzle-kit` config (`dialect: postgresql`, `schema`/`out` under `src/database/`, `strict`/`verbose` on, `DATABASE_URL` from env). Only used locally/in CI to run `generate`/`check`; `drizzle-kit` itself never ships in the production image.
- `package.json` — scripts: `dev` (tsx watch), `build` (tsc), `start` (node dist), `typecheck`, `lint`, `generate`, `migrate`, `db:seed`, `db:purge`, `clean` (`db:*` namespaced because bare `pnpm purge` is a builtin alias). Dependencies: `@fastify/{cookie,cors,helmet,rate-limit}`, `better-auth`, `close-with-grace`, `date-fns`, `drizzle-orm`, `fastify`, `fastify-type-provider-zod`, `nodemailer`, `pino`, `postgres`, `uuid`, `zod`; devDependencies: `@faker-js/faker`, `drizzle-kit`, `pino-pretty`, `tsx`, `typescript`, `@types/*`. Exact pins only (`.npmrc` `save-exact=true`).
- `tsconfig.json` — extends root `tsconfig.base.json`; `rootDir`/`outDir` set explicitly (tsc errors without `rootDir` once `outDir` is set on a single-directory `include`).
- `Dockerfile` — the one Dockerfile (`docs/decisions.md` #42): `base` → `deps` (full workspace `pnpm install`) → `dev` (copies `api` + `shared` source, `CMD` runs the dev server). `compose.yml` bind-mounts the source over it and overrides `command` to chain `migrate`. Multi-stage production build reference is `docs/production-runbook.md` §1.

## web (TanStack Start frontend)

- `src/routes/__root.tsx` / `src/routes/index.tsx` — placeholder route tree: a single index route rendering "Transactions Dispute Portal". Replace with real routes/loaders once the UI work starts. No UI kit/shadcn, forms, query client, or auth client yet — deliberately bare.

- `server.mjs` — the production entry point. TanStack Start's `vite build` emits `dist/server/server.js` as a **bare Web-standard `fetch` handler with no attached runtime** (confirmed by inspecting the build output and the `@tanstack/react-start` package — it's meant to be wrapped by a hosting adapter, not run directly). `server.mjs` wraps it with `srvx` (already a transitive dependency, promoted to direct) to get an actual Node HTTP server: `serve({ fetch: handler.fetch, port, hostname: "0.0.0.0" })`. Running `node dist/server/server.js` directly does nothing and exits 0 silently — this tripped up the first pass at the production Dockerfile.
- `package.json` — scripts: `dev` (vite dev), `build` (vite build), `start` (`node server.mjs`), `typecheck`, `lint`, `clean`.
- `tsconfig.json` — extends root `tsconfig.base.json`; includes `server.mjs` for typecheck (excluded from eslint, see Root section).
- `Dockerfile` — the one Dockerfile (`docs/decisions.md` #42): `base` → `deps` → `dev` (`CMD` runs `vite dev --host 0.0.0.0`), source bind-mounted via `compose.yml`. The `server.mjs` / `srvx` wrapper and the externalized-`react` SSR gotcha still matter for a real build — captured in `docs/production-runbook.md` §1.

Added to as concrete callers need, not speculatively.
- `src/schema/global.ts` — `globalResponseSchema` / `paginatedGlobalResponseSchema` / `paginationSortAndSearchQuerySchema`: the default response envelope for every API response — see `docs/api.md` "Response envelope" and `docs/decisions.md` #22.
- `src/schema/check.ts` — `healthzResponseSchema` / `readyzResponseSchema` (the envelope `.extend`ed with `data`).
- `src/schema/authentication.ts` — `authOtpRequestBodySchema` (`{ email }`) / `authOtpVerifyBodySchema` (`{ email, otp }`, the OTP regex/length from the `OTP` constant).

- `src/type/*.ts` — `z.infer` re-exports for each schema group (`field`, `global`, `check`, `authentication`, `transaction`, `dispute`): `Role`, `OrderDirection`, `DisputeStatus`, `DisputeReason`, `DisputeResolution`, `UuidParams<Key>`, `GlobalResponse`, `Transaction`, `Dispute`, `AdminDispute`, `DisputeResolveBody`, etc.
- `package.json` — `exports` points at `dist/index.js`/`dist/index.d.ts` (compiled), not `src/index.ts` directly — `api`'s production image ships a compiled `dist/app.js` run by plain `node`, which can't resolve a `.ts` import target. `dev` script (`tsc --watch`) keeps `dist/` fresh locally — `turbo dev` runs it in parallel with `api`/`web`'s own dev servers. All relative imports within `shared/src` use explicit `.js` extensions for this same reason — `moduleResolution: "Bundler"` doesn't rewrite them, and plain Node ESM requires them (caught while building `docs/decisions.md` #22's schema files: `tsc` passed, plain `node` on the compiled output didn't, until fixed).
- `package.json` dependencies — `zod@4.4.3` (already resolved in the lockfile as a transitive dependency before this).
- `tsconfig.json` — extends root `tsconfig.base.json`; `rootDir`/`outDir` set explicitly (same `rootDir` requirement as `api`).
